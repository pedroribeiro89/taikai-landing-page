# Kendo Landing Page — Hello World Foundation (Design)

**Date:** 2026-07-01
**Status:** Approved

## Purpose

Establish the foundation for a simple informational landing page for a Kendo
championship in Belo Horizonte. This first step delivers a minimal but real
Astro project (the same tooling the final site will use) plus an English
tutorial explaining how to configure the repository and deploy it to Netlify
with continuous deployment.

The actual content sections (banner, senseis, location, hotel suggestions) are
intentionally **out of scope** for this step. They will be added later once the
foundation is deployed and confirmed working.

## Decisions

- **Framework:** Astro (content-focused, ships zero JS by default, first-class
  Netlify support, easy to grow into components later).
- **Site language:** Portuguese (pt-BR) only.
- **Package manager:** pnpm. Netlify auto-detects pnpm from `pnpm-lock.yaml`.
- **Tutorial language:** English (`DEPLOY.md`).
- **Deploy flow:** GitHub → Netlify continuous deploy — connect the repo once,
  every push to the main branch auto-publishes. No drag-and-drop or CLI
  alternative documented.

## Components

### `src/pages/index.astro`
A tiny but real page in Portuguese so it already reads as the start of the site,
not a throwaway placeholder:
- Page `lang="pt-BR"`, proper `<title>` and meta charset/viewport.
- Heading: "Campeonato de Kendo — Belo Horizonte".
- A short "Em construção" (under construction) line.
- Minimal inline/base styling only — no design system yet.

No component breakdown (`<Banner>`, `<Senseis>`, etc.) at this stage.

### `netlify.toml`
Pins the build so Netlify setup is reproducible and the tutorial can say "just
connect the repo — it's already configured":
```toml
[build]
  command = "pnpm build"
  publish = "dist"
```

### `DEPLOY.md` (English)
Step-by-step tutorial covering:
1. Prerequisites — Node.js, pnpm, git, a GitHub account, a Netlify account.
2. Run locally — `pnpm install`, `pnpm dev`.
3. Build locally (optional sanity check) — `pnpm build`, `pnpm preview`.
4. Initialize git and push to a new GitHub repository.
5. Connect the repo to Netlify (continuous deploy — every push auto-publishes).
6. Where the live site URL appears and how to set a custom domain later.

## Data Flow

Static site generation only. `pnpm build` runs `astro build`, producing static
files in `dist/`. Netlify serves `dist/`. No runtime data, no APIs, no client
JavaScript required.

## Error Handling

Minimal, since this is a static scaffold. The main failure surfaces are:
- **Build fails on Netlify** — mitigated by pinning the build in `netlify.toml`
  and verifying `pnpm build` locally before pushing.
- **Wrong package manager on Netlify** — mitigated by committing
  `pnpm-lock.yaml` so Netlify auto-selects pnpm.

## Testing / Verification

- `pnpm install` completes cleanly.
- `pnpm dev` serves the page locally and it renders the pt-BR heading.
- `pnpm build` produces `dist/index.html` with the expected content.
- After deploy: the Netlify URL shows the page, and a subsequent push triggers a
  new deploy automatically.

## Out of Scope (YAGNI)

Real content sections, images, styling system/design tokens, multi-language
support, and any CMS. These come in later iterations once the foundation is
live.
